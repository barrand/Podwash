# Listening history implementation plan

**Status** Ready to implement in three work packages. The first release includes all three.

History gives listeners one place to find finished episodes across shows, read saved transcripts, and replay episodes after PodWash removes their audio downloads.

## First version

- Put **History** above subscriptions in Library, including when Library has no subscriptions. Open a dedicated screen in the existing Library navigation stack.
- Reuse the shared episode tile with the episode title and show name. Group by local listening date, with **Today**, **Yesterday**, and calendar dates. Keep one row per episode, newest completion first. Finishing a replay updates that row’s date.
- Use the end of a playback run as the completion event, including finishes after PodWash skips an intro or outro. Pause, resume, **Next**, and **Mark as Played** keep their current effects on playback and leave dated history intact. Import existing played episodes from the subscription catalog under **Previously marked played**. Finishing one promotes it to dated history. The empty state reads “Episodes you finish will appear here.”
- Use Library’s **Play**, **Download**, **Prepare**, progress, and recovery controls. **Play** from History starts from the beginning. **Download** and **Prepare** leave the current playback session in place and make **Play** available when ready. **View Transcript** appears in **⋯** when a saved transcript is available. **Play Next** places a replay in Up Next.
- Keep the history row after download cleanup, feed refresh, and unsubscribe. For a still-subscribed show, use a stored episode source if the local catalog entry is missing and its identity can be resolved safely. Unsubscribe keeps the history entry and clears the show’s downloads, analysis, transcripts, and playback progress. The row shows that replay is unavailable while unsubscribed. Update the unsubscribe confirmation to explain that History keeps the entry.

## A. History storage and Library screen

### Storage and upgrade

Keep the shipping `PodWash.xcdatamodel` in the model bundle and add a new current version. Add a local history entity keyed by the subscription’s feed URL key and episode ID. Store the latest completion date, title, show name, and the episode’s available playback metadata, including its last known enclosure. Keep the record independent of the subscription’s cascade-delete relationship. The RSS parser can return a raw GUID or a title-and-date ID, so two shows can produce the same identifier. Use the compound key for history writes, queries, and row identity. [RSS parser](../../PodWash/PodWash/RSSParser.swift#L228) · [Core Data model](../../PodWash/PodWash/PodWash.xcdatamodeld/PodWash.xcdatamodel/contents)

Import the existing `isPlayed` flags from episodes attached to a valid subscription. Run the import after opening the upgraded store and before startup work can change played flags or catalog membership. Write the import and its completion marker together so a failed launch can retry. Preserve any existing dated row on retry. Give undated rows a stable show-and-title order and use the compound key to break sort ties. Publication dates and show-level activity timestamps serve their existing purposes. [Persistence controller](../../PodWash/PodWash/PersistenceController.swift) · [Resume position store](../../PodWash/PodWash/ResumePositionStore.swift)

### Completion and screen updates

Bind the engine’s end callback to the episode and playback run that generated it. Accept it once for that run and reject callbacks from a replaced engine or a run already left through **Next**. Media-services recovery and paused restore keep the same run when they continue interrupted playback. Persist the run’s identity with the active session and its completion with the history upsert, so reopening an ended session while Up Next was waiting cannot date it again. An accepted replay from the beginning starts a new run, including when it reuses the same engine. Save completion and the existing played-state update together before cleanup or queue advance. If the write fails, leave the transaction consistent and report the error through existing diagnostics without preventing playback from advancing. [Playback engine](../../PodWash/PodWash/PlaybackEngine.swift#L205) · [Shell completion handler](../../PodWash/PodWash/AppShellModel.swift#L1346) · [Queue completion handler](../../PodWash/PodWash/QueueCoordinator.swift#L93)

Build the History destination on `SharedEpisodeRow` and the shell’s existing transcript and preparation issue sheets. Use a lazy list with the mini-player’s bottom clearance and stable accessibility identifiers. Recompute completion groups when the local day or time zone changes. Refresh visible row actions from the existing catalog, download, preparation, queue, and transcript notifications without requerying history on each playback tick. Show the existing readiness status and a specific unavailable state for an unsubscribed show, a missing source, or an unresolved ID collision. [Library navigation](../../PodWash/PodWash/AppShellView.swift#L450) · [Shared episode row](../../PodWash/PodWash/EpisodeRowView.swift)

## B. Replay and transcript access

### Resolve the source and start playback

Use a single history-aware resolver for explicit actions. Prefer the catalog entry for the same feed, then use the stored source when the show is still subscribed and the episode is absent. The regular RSS merge already keeps episodes omitted from later responses, so test the fallback with an actually missing catalog row. History playback and preparation may use the fallback without adding the episode to the show catalog or smart autoplay. Pass the resolved identity through consent, the serial warm worker, action revalidation, issue and retry handling, and paused-session restore. Persist the expected feed alongside the active episode ID for a History session. Existing sessions can continue resolving through the catalog. [Feed merge](../../PodWash/PodWash/PodcastStore.swift#L57) · [Warm planner](../../PodWash/PodWash/WarmPlanner.swift#L220) · [Paused-session store](../../PodWash/PodWash/NowPlayingSessionStore.swift)

Playback and disk caches currently use bare episode IDs. Before using them for a History row, check that the catalog, active work, and retained records establish which feed owns the ID. If association is ambiguous, retain the History metadata and show that playback is unavailable. Offer a transcript only when it can be attributed to the row’s feed. Apply the same ownership check to unsubscribe cleanup and to in-flight completions after a refresh or unsubscribe. A newly downloaded enclosure must use analysis for that audio. An enclosure URL update in feed metadata can leave an already verified local download usable under the existing source policy. [Catalog lookup](../../PodWash/PodWash/PodcastStore.swift#L201) · [Download and replacement path](../../PodWash/PodWash/WarmPlanner.swift#L523)

Carry explicit replay intent independently of `isPlayed`, which can be false after a previous replay started. Route History **Play** through the shell’s prepared-local handoff. Revalidate the source, file, settings, and request after asynchronous staging. At the accepted start, reset the resume position and played flag and start at zero. If the same episode is ready in the current engine, deliberately restart it from zero. If fresh preparation would replace assets used by the active episode, show **Currently playing** until the session releases those assets. Preparation keeps the previous completion date and position and leaves other playback alone. A stale or rejected play request leaves the previous state intact. [Local playback handoff](../../PodWash/PodWash/AppShellModel.swift#L1531) · [Replay reset](../../PodWash/PodWash/ResumePositionStore.swift#L55)

### Keep saved transcripts readable

Before invalidating analysis for a fresh replay, quiesce prior work for the episode and retain the last readable transcript in a display-only cache scoped to the history episode. Keep it available during preparation, cancellation, and failure. The fresh worker uses the current audio and its own transcript and interval caches, including when retrying a partial cloud result. Publish the replacement for the accepted generation only. While displaying the old transcript, show text without seeking, live follow, or cleaning timestamps from a different audio revision. Clean up the display-only copy once a valid replacement is available. Gate **View Transcript** on cache availability. Validate on open and refresh the affordance if a file was deleted or unreadable. [Current replay cleanup](../../PodWash/PodWash/AppShellModel.swift#L1258) · [Partial analysis retry](../../PodWash/PodWash/AnalysisPipeline.swift#L353) · [Transcript cache](../../PodWash/PodWash/TranscriptCache.swift)

On unsubscribe, gather both catalog and history episode IDs owned by that feed. Block new action starts for the feed while cleanup is in progress. Invalidate its staged playback, pending consent, queue entries, replay owners, and durable active session. Wait for its workers before deleting audio, both transcript caches, analysis, and any progress rows left outside the catalog. Rebuild the History and Queue views after the subscription change. [Unsubscribe](../../PodWash/PodWash/AppShellModel.swift#L1153) · [Unsubscribe confirmation](../../PodWash/PodWash/AppShellView.swift#L228)

## C. Play Next for replay

Persist the expected history feed on an explicit replay queue entry, with an empty value for regular entries. Use typed entry snapshots for reorder, remove, clear, Undo, and relaunch so restoring order also restores intent. Promote an existing entry without duplicating it. Omit **Play Next** for the episode currently playing, which already has an explicit restart action. Use the same replay-aware source and readiness across Queue presentation, manual advancement, and the existing CarPlay queue integration. Show replay eligibility in manual Up Next while smart autoplay continues to use the subscription catalog and its played filter. [Queue store](../../PodWash/PodWash/QueueStore.swift) · [Upcoming plan](../../PodWash/PodWash/AppShellModel.swift#L1917) · [CarPlay queue](../../PodWash/PodWash/CarPlayQueueDataSource.swift)

Keep the existing **Auto-download new episodes** preference and bounded preparation window. With auto-download off, a queued replay can play when ready and the tile can start preparation explicitly. Before a queued replay can advance, require a verified local file and the current cleaning requirements. When it is still preparing, use the existing next-ready and pending-advance policy. A terminally unavailable replay remains visible for recovery or removal and does not count as work in progress. Keep one serial preparation owner per episode when a History action and Up Next request the same work. [Preparation window](../../PodWash/PodWash/UpcomingSelectionPolicy.swift) · [Warm planner](../../PodWash/PodWash/WarmPlanner.swift#L220)

The current queue coordinator removes an entry before invoking a void playback callback. For a replay, stage playback first and revalidate the exact queue entry and source after the await. At acceptance, commit the replay reset, queue consumption, and durable active episode together. A failed or superseded start leaves the replay queued and keeps the resume state. Pass the explicit replay intent through queue advancement so the start neither resumes the previous position nor puts a finished predecessor back in Up Next. Distinguish **Next** from natural completion so an interrupted episode stays resumable. [Queue handoff](../../PodWash/PodWash/QueueCoordinator.swift#L131) · [Manual ready playback](../../PodWash/PodWash/AppShellModel.swift#L1577)

## Acceptance checks

| Work package | Scenario | Expected result |
| --- | --- | --- |
| A | Open a SQLite store created with the shipping model, then launch twice | Subscriptions, resume positions, current session, and queue order survive. The legacy import runs once. Undated rows have no fabricated date. |
| A | Finish episodes across shows, replay one, cross midnight, and relaunch | History updates immediately, displays one row per episode, groups by local completion date, and restores the latest completion on launch. |
| A | Pause, mark played, skip while the next episode is preparing, or deliver a stale end callback | These actions leave prior completion dates intact. Duplicate callbacks and relaunch during a pending queue advance preserve the same completion. A new replay can finish independently. |
| A | Open History with an empty Library or large text | History remains reachable, empty copy is clear, and the final row and its actions scroll above the mini-player. |
| B | Clean up audio, then prepare a replay with a saved transcript | The saved transcript opens without downloading audio and stays readable after cancellation or failure. A fresh-ASR or cloud retry uses the current audio. Successful replay starts at zero when accepted. |
| B | Use a History record whose episode is missing from a subscribed show’s catalog | Replay resolves through the stored source, survives a paused-session relaunch, and never inserts the episode into the show catalog. A same-ID episode from another feed cannot supply audio or a transcript to the wrong row. |
| B | Unsubscribe during consent, analysis, or a staged start | History keeps the row. Playback becomes unavailable and scoped downloads, transcript files, queue entries, and progress are removed without touching another feed’s data. |
| C | Queue a played episode with auto-download on and off, then reorder, clear, Undo, and relaunch | Replay intent survives queue mutations and is visible in Up Next. The auto-download preference governs background work. Explicit preparation and other ready queue entries remain usable. |
| C | Invalidate a queued replay’s source or remove the entry while playback is staging | The stale attempt neither starts playback nor consumes a newer entry. An accepted replay starts once from zero, leaves the History date intact until it finishes, and keeps other played episodes out of smart autoplay. |

Run focused checks through `scripts/verify.sh` after each package. Add a version-to-version SQLite migration test in `PersistenceMigrationTests`, cover playback and queue races alongside `EpisodeRowActionTests` and `QueueTests`, and extend the transcript tests to cover the display-only copy and fresh-analysis retry. The final gate is the full suite plus a simulator pass for VoiceOver and large text. [Verification script](../../scripts/verify.sh)
